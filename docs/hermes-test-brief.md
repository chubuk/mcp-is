Методология: `docs/mcp-acceptance-checklist.md` (уровни 0–7 + два главных правила).
Два правила сильнее всего: (1) клиент не патчится, пока серверный баг не доказан probe'ом
по сырому протоколу; (2) каждая проверка содержит контрпример — действие, которое обязано
НЕ сработать.

## Правила безопасности (нарушение = повтор инцидента 02.11)

1. **НЕ запускать импорт** (никаких «заменить каталог»). Импорт — главный подозреваемый в уничтожении 15 товаров.
2. **НЕ удалять и не массово обновлять** существующие 17 товаров. Восстановленные 15 — только чтение.
   Тестовые `1947370801` / `1947379265` — можно менять, но вернуть значения как было.
3. Все эксперименты со записью — на отдельном товаре `zzz-hermes-test`, который создаёшь сам
   и **удаляешь в конце** (и проверяешь, куда он делся: в корзину или навсегда — это тоже пункт проверки!).
4. Каждая запись подтверждается **перечитыванием** (read-back), не текстом «успех».
5. Если что-то пошло не так — НЕ чинить молча импортом/удалением; зафиксировать и доложить.

## Что проверить (порядок — от чтения к записи)

### 1. Discovery
- `tools/list`: `get_seo`/`update_seo` на месте (core surface); в `update_product` есть
  `clear_fields`, НЕТ `quantity` и `price` (цена/остаток — только через `update_variant`).
- Контрпример: `get_seo` c `resource_type:"zzz"` → ошибка, не тишина.

### 2. Пагинация (считать items!)
- `list_products` `per_page:3` → ровно 3; `per_page:"3"` (строка!) → 3;
  `page:5, per_page:3` → товары 13-15; `per_page:250` → 17/17.
- `total` в конверте = размер выдачи, НЕ каталога (для подсчёта — `get_products_count`, он не в core, вызывается через `call_insales_tool`).

### 3. Живые данные (кешей нет)
- После любого своего изменения соседнего объекта повторный запрос видит его сразу
  (без ожидания, без «освежения»).

### 4. Записи на `zzz-hermes-test` (создать → всё ниже → удалить)
1. `create_product` (title, price, sku, quantity) → товар виден в админке, счётчики секций/склада выросли.
2. `update_product` с мусорным ключом (`zzz_probe_field`) → в ответе `ignored_keys`, товар не изменился.
3. `update_product` с `title:""` → Название не затёрлось (пустые значения не пишутся).
4. `update_seo` (html_title/meta_keywords/meta_description) → `get_seo` показывает ровно их;
   ещё один `update_seo` с мусорным ключом → `ignored_keys`.
5. `clear_fields:["meta_keywords"]` → поле реально пустое (null) после перечитывания.
6. `update_variant` c `quantity:0` → остаток реально 0 (нули — легитимная запись!) → вернуть исходный остаток.
7. `add_product_to_collection` → счётчик секции вырос; `remove_product_from_collection` → вернулся.
8. `delete_product` → исчез из списка/админки. **Зафиксировать: попал ли в «Корзину»
   (Импорт/Экспорт → Корзина) или удалился навсегда.**
9. Контрпример: `get_product` с несуществующим id → ошибка.
