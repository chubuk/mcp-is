### Исправления (2026-11-13, задеплоены и проверены живьём)

1. **Returning user → сразу в панель** (`web/static/js/auth.js`): при пустом `api_key` проверяются ключи через `GET /api/ai-keys`; ключи есть → `App.navigate('/dashboard')` («показать интерфейс» по вендору, docs/dev/02:91); ключей нет → честный экран «создайте в разделе AI-ключи».
2. **HTTPS round-trip** (`app_install.go`): `https://<shop>/admin/applications/...` — Secure-куки админки больше не теряются на http-хопе (также закрывает SSL-гэп №1).
3. **Сгоревший код не сносит сессию**: `POST /api/exchange-code` отдаёт 400 (не 401) на невалидный/сгоревший код — глобальный SPA-обработчик 401 очищал localStorage-JWT при reload/back на /onboarding; плюс guard повторного обмена при живой сессии.

**Live-верификация 2026-11-13 (Playwright, вход из админки `/admin2/applications/6278793/enter`):**
- Прогоны 1 и 2: `/app` 302 → `/autologin` 302 → `/onboarding` → exchange **200** → **`/dashboard`** («Добро пожаловать, chubuk!») — без единого экрана авторизации.
- Reload/back на `/onboarding`: exchange **400** (сгоревший код), сессия не сброшена → отскок в `/dashboard`.
