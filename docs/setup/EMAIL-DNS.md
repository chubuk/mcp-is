# Email: DNS (SPF, DKIM, DMARC) и SMTP

Краткая инструкция: какие DNS-записи нужны, чтобы письма из MCP IS доходили и не падали в спам.
Скрипт проверки: `./scripts/check-email-dns.sh [домен]`.

---

## Кратко: 3 записи

| Тип | Имя | Значение | Зачем |
|-----|-----|----------|-------|
| **TXT** | `@` | `v=spf1 include:_spf.mail.ru ~all` | SPF — кому разрешена отправка от имени домена |
| **TXT** | `_dmarc` | `v=DMARC1; p=none; rua=mailto:dmarc@ваш-домен` | DMARC — политика + отчёты |
| **TXT** | `<selector>._domainkey` | `v=DKIM1; k=rsa; p=…` | DKIM — криптографическая подпись (из панели почты) |

Плюс **MX**, если нужен приходящий ящик в домене (`noreply@ваш-домен`).
Для отправки через внешний SMTP (Mail.ru) без доменного ящика MX не обязателен.

**SPF только один** на домен. Если уже есть — добавьте `include:` в существующий, не создавайте второй.

---

## Два режима отправки

### A. Быстро (без DNS)
SMTP `smtp.mail.ru:587`, **`SMTP_FROM` обязательно `…@mail.ru`** (выровнено по домену провайдера).

### B. С доменом (правильно)
1. Подключить домен в почтовом сервисе (Mail.ru для домена / Яндекс 360).
2. Завести ящик `noreply@ваш-домен`, включить исходящий SMTP.
3. В панели сервиса взять **MX** и **DKIM** → в DNS.
4. Добавить **SPF** + **DMARC** (таблица выше).
5. `SMTP_FROM=MCP IS <noreply@ваш-домен>`.
6. **Пароль приложений** (см. ниже) — не основной пароль ящика.

## Mail.ru (biz / «Почта на домене»): пароль приложений

Mail.ru для сторонних программ требует **пароль приложений**, обычный пароль от ящика не подойдёт.

1. Почта → **Настройки** → Безопасность → [Пароли для внешних приложений](https://account.mail.ru/user/2-step-auth/passwords/) → **Создать**.
2. Тип: **«Только отправка писем»** (или «Полный доступ к Почте»).
3. Скопируйте пароль сразу (повторно не показывают).

```env
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465
SMTP_USER=support@ваш-домен
SMTP_PASS=<пароль приложений>
SMTP_FROM=Сервис <support@ваш-домен>
```

Админка: **Почта** → TLS **SSL**, порт **465** (или STARTTLS / 587).

**`535 Application password is REQUIRED`** — вставлен основной пароль ящика. Создайте пароль приложений.

**Timeout при подключении** — порты SMTP закрыты на VPS (на многих тарифах так по умолчанию, например RuWeb). Напишите в поддержку хостера: открыть исходящий 25/465/587 с IP сервера.

## DMARC: старт → ужесточение

```
v=DMARC1; p=none; rua=mailto:dmarc@mcp-is.ru; fo=1
```

Через 2–4 недели, если в отчётах нет легитимных отказов:

```
v=DMARC1; p=quarantine; pct=100; rua=mailto:dmarc@mcp-is.ru
```

Политика `reject` — только когда всё стабильно.

## Проверка

```bash
./scripts/check-email-dns.sh mcp-is.ru
./scripts/test-smtp.sh you@example.com   # нужен SMTP_* в .env или в админке
```

В админке: **Почта** (`/admin/email`) — карточка «DNS-записи домена» с этими же подсказками.

---

## Если записей нет

- Письма могут уходить, но чаще в «Спам» или отклоняться Gmail/Yandex/Mail.ru.
- Без SPF в `From` на чужой домен — жалобы и блокировки.
- DKIM без SPF/DMARC — лучше, чем ничего, но неполноценно.

Документация протокола SMTP: RFC 5321/5322, порты 465 (SSL) / 587 (STARTTLS) — см. также `docs/setup/INSALES-APP.md`, `INSTALL.md`.
