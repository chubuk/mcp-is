# MCP IS — Часто задаваемые вопросы

## Установка и запуск

### Как получить ключ InSales?

1. Войдите в панель администратора магазина InSales
2. Перейдите: **Расширения → Разработчикам → Ключи доступа**
3. Нажмите **Создать ключ доступа**
4. Скопируйте **Идентификатор** (ID) и **Пароль**

### Почему Docker контейнер не запускается?

Проверьте:
- Docker установлен: `docker --version`
- Порты свободны: `sudo lsof -i :80` и `sudo lsof -i :443`
- .env файл заполнен: `cat .env`

### Как сменить порты nginx?

В `.env`:
```bash
NGINX_HTTP_PORT=8888
NGINX_HTTPS_PORT=8443
```

Затем: `docker compose up -d`

## AI-клиенты

### Почему AI не видит write-команды?

Включён режим "Только чтение" или вы смотрите на core surface. Проверьте:
- В `.env`: `MCP_READ_ONLY=false`
- Или в Web UI: Магазины → редактировать → снять галку "Только чтение"
- **`tools/list` по умолчанию возвращает core surface (~30 tools)**, а не все 284. Для редких операций AI вызывает `search_insales_tools` → `call_insales_tool`, либо задайте `MCP_TOOLS_MODE=all`

### Как AI работает с пользовательскими полями товаров?

1. `list_product_fields` — справочник (`handle`, `title`, `type`)
2. `get_product` / `list_product_field_values` — значения с `handle`/`title`
3. `create_product_field_value` / `update_product_field_value` — запись по `product_field_id` **или** `product_field_handle`

Поля вариантов/коллекций — `*_variant_field_value`, `*_collection_field_value` (у collection в API только list/get/update).

### AI получает ошибку 401 "invalid API key"

- Убедитесь что ключ скопирован полностью (64 символа)
- Проверьте что ключ не отозван в разделе AI-ключи
- Убедитесь что заголовок `Authorization: Bearer <ключ>` указан верно

### MCP-клиент не подключается к серверу

Проверьте:
- Сервер запущен: `curl http://localhost:8080/health`
- URL указан верно: `http://localhost:8080/mcp`
- Если клиент в Docker: используйте `http://host.docker.internal:8080/mcp`

## Магазины

### Как добавить второй магазин?

1. Получите второй ключ InSales для нового магазина
2. В Web UI: Магазины → + Добавить
3. Заполните данные нового магазина
4. Сгенерируйте новый AI-ключ для этого магазина

### Как работает "Магазин по умолчанию"?

Если у пользователя несколько магазинов, AI автоматически использует магазин, помеченный как "по умолчанию". Для работы с другим магазином — переключите его как основной.

## HTTPS и сертификаты

### Как настроить HTTPS?

1. В Web UI: Сервер → Включить HTTPS
2. Укажите домен (должен указывать на ваш IP)
3. Укажите email для Let's Encrypt
4. Нажмите "Выпустить сертификат"

### Сертификат истекает — что делать?

Автоматическое обновление настроено по умолчанию. Если не работает:
1. Сервер → Статус сертификата
2. Нажмите "Продлить сертификат"
3. Проверьте логи: `docker compose logs nginx`

### Can't use Let's Encrypt на localhost?

Let's Encrypt не работает с `localhost`. Используйте:
- Самоподписанный сертификат (по умолчанию)
- Реальный домен для production

## Биллинг и аудит

### Как включить платную подписку для InSales-приложения?
В `.env` задайте `BILLING_MONTHLY=<сумма в рублях>`. При автологине создаётся `recurring_application_charge`; без активного платежа MCP-ключ не выдаётся. Подробнее: `docs/setup/INSALES-APP.md`.

### Где логи вызовов write-инструментов?
Таблица `audit_log` (tool, action, args_hash — без сырого payload для ПДн). Записывается при каждом write-вызове MCP tools.

## Технические вопросы

### Почему super_admin получает запрос на смену пароля?

При регистрации первого пользователя (super_admin) автоматически устанавливается флаг обязательной смены пароля. При первом входе система требует задать безопасный пароль. При последующих входах запрос не появляется. Механизм также доступен для других пользователей через API (поле `require_password_change` в БД).

**Требования к новому паролю:**
- Минимум 8 символов
- Хотя бы одна заглавная буква
- Хотя бы одна цифра

### Как посмотреть логи?

```bash
# Все сервисы
docker compose logs -f

# Только API
docker compose logs -f app

# Только nginx
docker compose logs -f nginx
```

### Как перезапустить сервис?

```bash
docker compose restart app
```

### Как обновить версию?

```bash
git pull
docker compose build app
docker compose up -d
```

### Как сделать бэкап?

Автоматические бэкапы настраиваются в админке (Настройки сервера → Бэкапы) и выполняются по расписанию. Вручную:

```bash
# Бэкап БД
docker exec mcp_is_db pg_dump -U admin mcp_is | gzip > backup.sql.gz

# Или через скрипт проекта
/opt/mcp-is/scripts/backup.sh

# Бэкап .env
cp .env .env.backup
```

## Персональные данные (152-ФЗ)

### Как работает защита персональных данных?

При работе с AI-моделями персональные данные клиентов (email, телефон, ФИО) могут передаваться LLM-провайдеру. MCP IS предоставляет механизм контроля:

1. **Включить защиту** — в настройках магазина или AI-ключа поставьте галку «Защита персональных данных»
2. **Маскировка** — email замаскировывается (`i***@domain`), телефон (`+7 (***) ***-**-**`), ФИО (`И***`)
3. **Журнал доступа** — каждый запрос к персональным данным логируется

**Как включить/выключить:**
- В Web UI: в списке AI-ключей нажмите «✅ ПДн» / «☐ ПДн» или кнопку «✏️ Ред.»
- Через API: `PUT /api/ai-keys/{id}` с телом `{"pdn_enabled": true/false}`
- В настройках магазина: аналогично, чекбокс «Защита персональных данных»

### Как определить юрисдикцию магазина?

Система автоматически определяет юрисдикцию по домену магазина:
- `*.myinsales.ru` — Россия (152-ФЗ)
- `*.myinsales.kz` — Казахстан
- `*.myinsales.by` — Беларусь

### Что такое автоПДн?

АвтоПДн — автоматическая защита персональных данных. Система сама определяет, нужно ли включать защиту, на основе юрисдикции магазина, расположения сервера и LLM-провайдера.

**Правила автоПДн:**
- Сервер **не в России** + магазин **российский** → защита **включена**
- Сервер **в России** + магазин **российский** + **зарубежная** LLM → защита **включена**
- Сервер **в России** + магазин **российский** + **российская** LLM → защита **выключена**

**Конфигурация:**
- `.env`: `SERVER_COUNTRY=RU` — страна расположения сервера
- `.env`: `PDN_AUTO_PROTECT=true` — включить/выключить автоПДн
- Админ-панель: вкладка «ПДн» → чекбокс «АвтоПДн»

**Производительность:** Вычисление автоПДн происходит при старте сервера и кешируется. При каждом MCP-запросе — только чтение из кеша (0 запросов к БД).

### Что происходит если галки выключены?

Если автоПДн отключена (`PDN_AUTO_PROTECT=false`), защита применяется только если включена вручную (галки в магазине или AI-ключе).

**Автоматическое определение юрисдикции магазина:**
- `*.myinsales.ru` → Россия (RU)
- `*.myinsales.kz` → Казахстан (KZ)
- `*.myinsales.by` → Беларусь (BY)
- Другие домены → Международный (INTL)

**Автоматическое определение LLM-провайдера:**
- Claude, OpenAI, GPT → США (US)
- YandexGPT, SberGPT → Россия (RU)
- Другие → Неизвестно (UNKNOWN)

**Правило автозащиты (152-ФЗ):**
Если магазин в юрисдикции **Россия (RU)** И LLM-провайдер **не российский** (не RU) → защита персональных данных включается **автоматически**.

**Примеры:**
| Магазин | LLM | Автозащита |
|---------|-----|------------|
| myshop.myinsales.ru | Claude Desktop | ✅ Включена (RU + US) |
| myshop.myinsales.ru | YandexGPT | ❌ Не включена (RU + RU) |
| myshop.myinsales.kz | Claude Desktop | ❌ Не включена (KZ ≠ RU) |
| myshop.shopify.com | Claude Desktop | ❌ Не включена (INTL ≠ RU) |

### Кто может настраивать защиту ПДн?

- Пользователь — для своих магазинов и AI-ключей
- Super_admin — для всех магазинов и ключей, а также глобальные настройки
