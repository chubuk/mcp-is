# Приложение InSales (стороннее приложение)

MCP IS может работать как **официальное внешнее приложение InSales**: магазин устанавливает его из бэк-офиса, получает MCP-ключ и подключает AI-клиент (Claude, Cursor, MiMoCode и др.).

> **Лицензия (BSL 1.1).** Коммерческое использование проекта (в том числе платное приложение или отдельный сервис для клиентов) **не разрешено без согласия разработчика** — Vladislav Chubuk &lt;chubuk@mail.ru&gt;. Личное, учебное и тестовое использование — свободно. С 2030-01-01 — Apache 2.0. Подробнее: `README.md`, `LICENSE`.

## Как это работает

1. **Установка.** InSales вызывает `GET https://<DOMAIN>/install?shop=&token=&insales_id=`.  
   Пароль магазина: `password = MD5(token + secret_key)`. После ответа `200 OK` приложение считается установленным.
2. **Вход.** Пользователь открывает «URL входа» приложения → `GET /app` → редирект в InSales для автологина → `GET /autologin?token3=...`.  
   `token3 = MD5(nonce + user_email + user_name + user_id + email_сonfirmed + password)`.
3. **Ключ.** Новый email — аккаунт создаётся автоматически, показывается MCP-ключ. Существующий email — нужно **войти своим паролем** и подтвердить привязку магазина (защита от захвата аккаунта).
4. **Удаление.** InSales вызывает `GET /uninstall?shop=&token=<password>&insales_id=` → магазин отвязывается.

## Переменные окружения

```bash
# Идентификатор приложения (Basic-auth login, один на все магазины)
INSALES_APP_KEY=myapplogin

# Секрет приложения (из карточки приложения, никому не сообщать)
INSALES_SECRET_KEY=mysecret
```

Оба обязательны. Если не заданы — режим приложения выключен (`/install` и `/autologin` отвечают 404), персональный режим с API-ключом магазина работает как раньше.

## Один сервер — много магазинов (иерархия ключей)

Один инстанс mcp-is.ru обслуживает все установки приложения. Ключей два уровня:

| Уровень | Что это | Где хранится | На магазин |
|---|---|---|---|
| Приложение | `INSALES_APP_KEY` + `INSALES_SECRET_KEY` — «Идентификатор» и «Секрет» из карточки | `.env` (один раз навсегда) | общие для всех |
| Магазин | пароль `MD5(token + secret)` из колбэка `/install` | БД: `app_installs.api_password_encrypted` (AES-GCM), при входе копия в `shops` | уникальны, строка на магазин |

Потоки обращений:

1. **InSales → наш сервер** (URL из карточки): `GET /install`, `GET /app`, `GET /uninstall`
   на `mcp-is.ru` — адреса общие, параметры (`shop`, `token`, `insales_id`) уникальны на магазин.
2. **Наш сервер → InSales** (REST API магазина): `https://<shop>.myinsales.ru/admin/...`,
   Basic-auth — логин `INSALES_APP_KEY` (общий), пароль пер-магазинный из БД.

При тысяче установок в `.env` ничего не меняется — растёт только БД.

### Детали

- **Ротация секрета.** Предположительно перевыпуск «Секрета» в карточке влияет только на
  новые установки: пароль магазина — это `MD5(token + secret)`, вычисленный в момент
  установки, и уже установленные магазины продолжают работать на сохранённых паролях.
  Vendor-дока InSales семантику ротации явно не описывает — проверить на реальном
  перевыпуске. При переустановке магазина пароль считается заново — с тем секретом,
  который в `.env` на тот момент.
- **Переустановка.** InSales шлёт `/install` повторно; запись в `app_installs`
  обновляется (`ON CONFLICT (insales_id)`), пароль пересчитывается, копия в `shops`
  обновляется синхронно (иначе API-клиент работал бы со старым паролем), кэш
  API-клиента сбрасывается.
- **App-режим vs персональный режим.** Персональный режим (API-ключ самого магазина
  в `shops.api_key_id`) — для одиночных интеграций без установки приложения. App-режим —
  для маркетплейса: логин = `INSALES_APP_KEY` (общий на все магазины), пароль
  пер-магазинный. Режимы не смешиваются: у app-магазина в `api_key_id` лежит
  идентификатор приложения, пароль — из `app_installs`.
- **Один `.env` на все магазины.** Никаких пер-магазинных переменных в `.env` быть не должно.

### Порядок первичной настройки

Ключевое правило: **сервер должен принять первый же коллбэк `/install`**, а он уходит
в момент создания карточки (см. ниже). Порядок:

1. Создать карточку в «Приложения → Разработчикам», скопировать показанные
   «Идентификатор» и «Секрет».
2. Положить их в `.env` как `INSALES_APP_KEY` / `INSALES_SECRET_KEY`, перезапустить app
   (в логах — «InSales app mode enabled»).
3. Удалить приложение из списка установленных и нажать «Установить» — коллбэк
   переиграется, теперь сервер его примет.

Если поле «Секрет» в карточке редактируемое прямо при создании (проверить на реальной
форме), можно подготовиться заранее и сократить окно: сгенерировать секрет
(`openssl rand -hex 16`), включить app-режим в `.env` до создания карточки и вставить
свой секрет в поле.

### Как это выглядит для пользователя

1. **Первичное создание карточки — особый случай.** «Разработчикам → Добавить новое
   приложение» → «Создать» → приложение сразу появляется в списке установленных
   (кнопки «Установить» в этот момент нет), InSales шлёт `/install` в момент создания.
   Если сервер не готов (app-режим выключен или коллбэк не дошёл) — записи в БД нет,
   а приложение выглядит установленным. Переиграть: удалить из установленных →
   в «Разработчикам» нажать «Установить».
2. Обычная установка/переустановка → `GET /install` → InSales требует 200 OK, иначе
   приложение не считается установленным.
3. Ссылка «открыть приложение» в админке — это «URL входа» с параметрами от InSales:
   `https://mcp-is.ru/app?shop=…&insales_id=…&user_id=…`. Дальше — обязательный
   InSales-круг (см. ниже): vendor разрешает его пропустить «если есть сессия приложения»,
   но наша сессия (JWT) живёт в localStorage SPA и серверу недоступна — поэтому
   на чистом браузере вход работал бы только через круг.
4. Круг: `/app` → одноразовый nonce в cookie → редирект в InSales
   `http://<shop>/admin/applications/<app_key>/login?token=<nonce>&login=https://mcp-is.ru/autologin`
   → InSales проверяет админ-сессию (нет — просит войти в бэк-офис) → возврат на
   `/autologin` с подписанной строкой. Два формата колбэка:
   - полный: `token3=MD5(nonce+user_email+user_name+user_id+email_сonfirmed+password)`
     (+ поля `user_email`, `user_name`, `user_id`, `email_сonfirmed`) — основной;
   - короткий: `token=MD5(nonce+password)` — **без данных пользователя**, работает
     только для установки, уже привязанной к пользователю; иначе 400.
5. `/autologin` валидирует подпись (constant-time) и создаёт/привязывает пользователя:
   новый email — создаются user + shop + AI-ключ; email уже привязан к этой же
   установке — вход без пароля (магазин/ключ не дублируются); существующий email без
   привязки — привязка только после входа паролем (защита от захвата). InSales не пишет
   в нашу БД напрямую — данные приходят проверенной подписью, а пишет их наш сервер.
6. Пользователь попадает в ЛК на mcp-is.ru уже авторизованным (`/onboarding`) и
   настраивает AI-ключи. Пароль магазина вручную не прописывается — он вычисляется
   из `token + secret` при установке.

> **Ограничение nonce.** Одноразовость nonce — cookie-based (TTL 300 с, серверного
> хранилища нет): повтор в этом окне теоретически возможен. Сессию защищает одноразовый
> HMAC-код (`/onboarding?code=`, TTL 2 мин) — он же ограничивает повторное использование.

## Публикация в маркетплейсе InSales

Публикация не меняет ключи и не требует их перевыпуска — маркетплейс это витрина над
той же карточкой приложения.

| Аспект | До публикации | После публикации |
|---|---|---|
| Ключи (`INSALES_APP_KEY`/`INSALES_SECRET_KEY`) | есть | **те же** |
| URL `/install`, `/app`, `/uninstall` | на mcp-is.ru | **те же** |
| Кто может установить | только добавленный тестовый магазин | любой магазин из каталога InSales |
| Комиссия InSales | не берётся | согласуется и устанавливается при публикации |
| «Стоимость» / триал | для теста | реально списывается (триал 14 дней) |
| Биллинг | неактивен | `RecurringApplicationCharge` при `BILLING_MONTHLY>0`; ключ не выдаётся, пока платёж не активен |

Перед публикацией: синхронизировать «Стоимость» в карточке с `BILLING_MONTHLY` в `.env`.

> **Отдельный сервис.** Если mcp-is развёрнут как самостоятельный инстанс и пользователи должны регистрироваться на сайте сами, в `.env` поставьте `REGISTRATION_ENABLED=true` (по умолчанию `false` — пользователей создаёт админ).

## URL для карточки приложения в InSales

| Поле | Значение |
|------|----------|
| URL установки | `https://mcp-is.ru/install` |
| URL входа | `https://mcp-is.ru/app` |
| URL деинсталяции | `https://mcp-is.ru/uninstall` |
| Идентификатор | = `INSALES_APP_KEY` |
| Стоимость | 0 — бесплатно; либо `BILLING_MONTHLY=<руб>` в `.env` (см. «Биллинг») |
| Триал | 14 (дефолт формы) |

> URL одни на все магазины — InSales вызывает их для каждого магазина со своими параметрами.

### Права (scopes)

- **Заказы** — доступ + «Импортировать заказы старше двух месяцев»
- **Клиенты** — доступ + персональные данные + телефон + email (для PDN-маскирования)
- **Товары** — доступ
- **«Отключить вебхуки от самого расширения»** — включить
- **Недоступно в странах** — не выбирать (без ограничений)

## Проверка после установки

```bash
# 1. Симуляция установки (secret=mysecret)
curl "https://mcp-is.ru/install?shop=test.myinsales.ru&token=token123&insales_id=123"
# → 200 OK, пароль MD5("token123mysecret") = 4c3f4c197336eb97475506e71c839c71

# 2. Здоровье
curl https://mcp-is.ru/health
```

Затем в бэк-офисе InSales нажмите «Войти в приложение» — после автологина появится MCP-ключ.

## Безопасность

- `email_сonfirmed` должен быть `true`, иначе автологин отклоняется.
- Ключ **не выдаётся** автоматически для уже существующего email — только после входа паролем.
- Пароли магазинов хранятся зашифрованными (AES-GCM), в логи не пишутся.
- Uninstall сравнивает пароль за constant-time.

## Биллинг (опционально)

По умолчанию приложение бесплатное (`BILLING_MONTHLY=0` — не задан).

| Переменная | Смысл |
|------------|--------|
| `BILLING_MONTHLY` | Ежемесячная сумма в рублях для `RecurringApplicationCharge`. `0` — бесплатно. |

При `BILLING_MONTHLY>0` после автологина:
1. Создаётся (или проверяется) `recurring_application_charge` в магазине.
2. Если InSales возвращает `confirmation_url` — пользователь перенаправляется на подтверждение оплаты.
3. Пока платёж не активен (`blocked`) — MCP-ключ **не выдаётся** (onboarding `?billing=pending`).
4. Активный charge (триал/оплата) — ключ выдаётся как обычно.

В карточке приложения InSales «Стоимость» можно указать 0 и продвигать биллинг через charge, либо заполнить тариф в карточке — синхронизируйте с `BILLING_MONTHLY`.
