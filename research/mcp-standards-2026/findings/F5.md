# F5: Ecosystem maturity & anti-patterns

## Findings

### [1] Official MCP Registry launched in preview on 2025-09-08 at registry.modelcontextprotocol.io as an open catalog/API for public MCP servers, with public/private sub-registries built on top of it.
- quote: "Today, we're launching the Model Context Protocol (MCP) Registry—an open catalog and API for publicly available MCP servers to improve discoverability and implementation."
- url: https://blog.modelcontextprotocol.io/posts/2025-09-08-mcp-registry-preview/ (via https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/blog/content/posts/2025-09-08-mcp-registry-preview.md)
- source_type: primary
- published: 2025-09-08
- confidence: high

### [2] Registry server names are reverse-DNS namespaced with exactly one slash (`io.github.user/weather`), enforced by pattern `^[a-zA-Z0-9.-]+/[a-zA-Z0-9._-]+$` in the 2025-12-11 server.schema.json; `_meta` extension keys use reverse-DNS namespacing for vendor data.
- quote: "Server name in reverse-DNS format. Must contain exactly one forward slash separating namespace from server name."
- url: https://static.modelcontextprotocol.io/schemas/2025-12-11/server.schema.json
- source_type: primary
- published: 2025-12-11 (schema version)
- confidence: high

### [3] Registry entries are version-immutable once published (npm-like), cannot currently be unpublished, and publisher `_meta` is capped at 4KB (4096 bytes of JSON).
- quote: "Submit a new server.json with a unique version string. Once published, version metadata is immutable (similar to npm). ... There is a 4KB size limit (4096 bytes of JSON). Publishing will fail if this limit is exceeded."
- url: https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/docs/registry/faq.mdx
- source_type: primary
- published: unknown (registry still in preview as of 2026)
- confidence: high

### [4] MCP now has a formal feature lifecycle with three states (Active / Deprecated / Removed) and a minimum deprecation window of at least twelve months, measured from the spec revision that marks the feature Deprecated (SEP-2596).
- quote: "Specify the minimum deprecation window: the number of months, at least twelve, that the feature MUST remain Deprecated before it is eligible for removal."
- url: https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/seps/2596-spec-feature-lifecycle-and-deprecation.md
- source_type: primary
- published: 2026 (first applied in 2026-07-28)
- confidence: high

### [5] Under the 2026-07-28 deprecations, Roots, Sampling, Logging, Dynamic Client Registration, and HTTP+SSE transport are Deprecated with earliest removal in the first revision on or after 2027-07-28; migration paths are documented in a public deprecated registry.
- quote: "Roots ... Deprecated in 2026-07-28 ... Earliest removal: First revision released on or after 2027-07-28" (same for Sampling, Logging, DCR; HTTP+SSE via SEP-2596)
- url: https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/docs/specification/2026-07-28/deprecated.mdx
- source_type: primary
- published: 2026-07-28
- confidence: high

### [6] Anthropic reports a typical multi-server MCP setup (GitHub, Slack, Sentry, Grafana, Splunk) consumes ~55k tokens in tool definitions before any work, and tool search reduces that by over 85% by loading only the 3–5 tools needed per request.
- quote: "A typical multiserver setup (GitHub, Slack, Sentry, Grafana, and Splunk) can consume ~55k tokens in definitions before Claude does any work. Tool search typically reduces this by over 85 percent, loading only the 3–5 tools Claude needs for a given request."
- url: https://docs.claude.com/en/docs/agents-and-tools/tool-use/tool-search-tool
- source_type: primary
- published: unknown (tool_search_tool_*_20251119 betas)
- confidence: high

### [7] Anthropic documents that Claude's tool-selection accuracy degrades once more than 30–50 tools are available; tool search keeps accuracy high even across thousands of tools.
- quote: "Claude's ability to pick the right tool degrades once you exceed 30–50 available tools. Because tool search loads only a focused set of relevant tools on demand, selection accuracy stays high even across thousands of tools."
- url: https://docs.claude.com/en/docs/agents-and-tools/tool-use/tool-search-tool
- source_type: primary
- published: unknown (same docs as [6])
- confidence: high

### [8] MCP 2026-07-28 client best-practices make progressive tool discovery the official pattern for large catalogs: fetch tools/list but defer injecting definitions, expose a lightweight `search_tools` meta-tool, and switch on when definitions exceed ~1–5% of the context window.
- quote: "The host fetches tool definitions via tools/list as normal, but defers injecting them into the model's context. The host provides a lightweight search_tools meta-tool to the model. ... Implement a threshold as a percentage of the context window. For example, 1%-5%."
- url: https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/docs/docs/2026-07-28/develop/clients/client-best-practices.mdx
- source_type: primary
- published: 2026-07-28
- confidence: high

### [9] The MCP roadmap (2026-08-22) explicitly names huge tool lists as a protocol-level problem — a 100-tool server charges the model for the entire surface before the first user question, and tool selection gets worse as the list grows — and starts a progressive discovery effort (small entry point, reveal catalog as conversation narrows).
- quote: "Connecting to a server with a hundred tools means the model pays for that entire surface before the user has asked a single question, and tool selection tends to get worse as the list grows. We're starting a progressive discovery effort so a server can offer a small entry point and reveal more of its catalog as the conversation narrows."
- url: https://blog.modelcontextprotocol.io/posts/mcp-roadmap/
- source_type: primary
- published: 2026-08-22
- confidence: high

### [10] Claude Code productizes progressive disclosure via ENABLE_TOOL_SEARCH (default: defer all MCP tools; `auto` loads upfront until definitions reach 10% of context; `auto:N` for custom %), `_meta["anthropic/alwaysLoad"]` per tool, and hard description caps of 4,096 chars (upfront) / 16,384 chars (via tool search).
- quote: "Threshold mode: Claude Code loads the tools it would otherwise defer upfront while their definitions total less than 10% of the context window, and defers all of them once the definitions reach 10% ... Server instructions, and the description of a tool that loads upfront: 4,096 characters ... The description of a tool that Claude loads through tool search: 16,384 characters"
- url: https://docs.claude.com/en/docs/claude-code/mcp
- source_type: primary
- published: unknown (Claude Code v2.1.2xx era)
- confidence: high

### [11] Official best practice for tool-heavy servers is not to dump a flat tools/list: hide bulk tools from default listing and serve them via search_tools; community article cites GitHub's 101-tool and Financial Modeling Prep's 253-tool setups recovering accuracy via deferred-loading, and reports field estimates of ~200–400 tokens per tool definition (50 tools ≈ 10–20K tokens).
- quote: "Hide bulk tools from tools/list; serve them through search_tools. ... GitHub's 101-tool and Financial Modeling Prep's 253-tool MCP setups both recovered accuracy through deferred-loading architecture after hitting the same cliff. ... ~200–400 tokens per tool definition the field reports"
- url: https://bex.co/blog/2026/09/23/mcp-progressive-discovery-100-tool-servers
- source_type: secondary
- published: 2026-09-23
- confidence: medium

### [12] Pre-connection server discovery is being standardized as MCP Server Cards (SEP-2127) — static metadata docs discovered via `<streamable-http-url>/server-card` or `/.well-known/ai-catalog.json` (RFC 8615) — separate from the Registry's server.json and from live `server/discover`.
- quote: "This SEP proposes adding a standardized, self-contained format to describe MCP servers for pre-connection discovery. ... Cards can be hosted at any unreserved URI, with <streamable-http-url>/server-card reserved as the recommended location. ... For automated domain-level discovery, an AI Catalog can be published at /.well-known/ai-catalog.json"
- url: https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/seps/2127-mcp-server-cards.md
- source_type: primary
- published: Draft (WG charter 2026-03-26)
- confidence: high

### [13] There is no MCP-wide i18n policy for server/tool metadata: the Server Card Working Group explicitly puts internationalization out of scope "until an MCP-wide i18n approach is defined"; the tool schema has no language/locale constraint on `description`, so English is the de facto norm and localized descriptions are neither standardized nor forbidden.
- quote: "Internationalization of Server Card content until an MCP-wide i18n approach is defined." (listed under Out of Scope)
- url: https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/docs/community/working-groups/server-card.mdx
- source_type: primary
- published: 2026-03-26 (charter)
- confidence: high

### [14] Official client guidance also recommends programmatic tool calling ("code mode") as the anti-dote to granular tool chains: model writes a script calling tools in a sandbox so intermediate results never enter context (illustration: ~100K+ tokens direct vs ~200-token script + ~15-token summary).
- quote: "Comparison of direct tool calling versus programmatic tool calling. Direct calling passes every intermediate result through the model (~100K+ tokens). Programmatic calling sends a ~200-token script to a sandbox, which executes the tool calls and returns a ~15-token summary."
- url: https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/docs/docs/2026-07-28/develop/clients/client-best-practices.mdx
- source_type: primary
- published: 2026-07-28
- confidence: high

## Dead ends
- WebSearch tool was unavailable for the whole session; searches went through DuckDuckGo HTML/lite (often rate-limited to empty) and direct fetches of known primary URLs.
- modelcontextprotocol.io docs site was unreachable (HTTP 000) from this environment; used raw.githubusercontent.com on modelcontextprotocol/modelcontextprotocol and blog.modelcontextprotocol.io instead.
- No primary source found that mandates English-only tool descriptions; the only norm-level signal is the Server Card WG i18n deferral [13].
- Independent benchmarks cited in the bex.co piece (RAG-MCP 43%→<14%, Nebula 95% vs 71%, TaskBench 96%→25%, MCPVerse 2025, Stephanie Goodman 143K-token measurement) were not fetched at their original sources and are therefore not standalone findings.
